# 罗密欧每日记账：产品与软件设计规格

> 英文名称：Romeo Daily Ledger  
> 规格日期：2026-08-29  
> 目标平台：macOS 14 及以上  
> 目标仓库：[DUGUSHUANGTAN/Romeo-Daily-Ledger](https://github.com/DUGUSHUANGTAN/Romeo-Daily-Ledger)  
> 开源许可证：MIT

## 1. 软件定位书

### 1.1 一句话定位

罗密欧每日记账是一款安静、本地优先、可由 AI 辅助录入和分析的开源 Mac 每日账本。

### 1.2 核心用户

1. 首要用户是项目作者本人，用于稳定、轻量的日常收支记录。
2. 次要用户是重视数据所有权、隐私、离线能力与可定制性的 Mac 用户。
3. AI 用户愿意自行配置远端模型连接，不依赖应用开发者提供账号、代理服务或共享密钥。

### 1.3 产品原则

- **本地所有权**：账本数据默认只保存在当前 Mac，不需要注册或登录。
- **手动功能优先**：无网络、无 AI 连接时，全部基础记账功能仍正常工作。
- **AI 可选且可逆**：AI 只生成可编辑草稿或只读分析，不直接覆盖、修改或删除现有账目。
- **协议驱动**：AI 连接按 API 协议配置，不展示或绑定模型厂家列表。
- **清楚胜于丰富**：首页服务快速记账，日历服务时间回看，统计只提供足够有用的基础洞察。
- **高风险操作可恢复**：删除、导入和恢复均提供确认、预览、撤销或自动快照。
- **原生 Mac 体验**：鼠标与键盘并重，遵循系统无障碍和减少动态效果设置。

### 1.4 竞争边界

本产品不是资产管理工具、多人财务系统、云端记账服务或银行账户聚合器。首版不追求预算规划、投资追踪、票据识别或跨设备同步。

## 2. 成功标准

- 正常情况下，用户可在 10 秒内完成一条手动账目。
- 无网络或无 AI 配置时，记账、编辑、日历、统计、导入导出和设置均可使用。
- 任意账目保存后仍可修改日期、类型、金额、分类和备注。
- 同一界面只使用用户选定的系统语言，不混用中英文系统文案。
- API 密钥不进入日志、SwiftData、备份文件、导出文件或 Git 仓库。
- 备份恢复与导入导出通过往返一致性测试。
- 发布版只在用户点击“检查更新”后访问项目 GitHub 更新源，安装前必须再次确认。
- AI 响应异常时不产生未经用户确认的账目。
- 完整账本分析分批进行时，已处理账目数必须等于源账目数，不允许静默截断。
- 深浅主题、字体切换、动效强度、键盘导航和 VoiceOver 均可用。

## 3. v1 功能范围

### 3.1 基础记账

- 支持支出与收入两种账目类型。
- 支持新增、查看、编辑和删除账目。
- 每条账目包含金额、类型、分类、发生日期与时间、备注、创建时间和修改时间。
- 金额必须大于零，使用十进制定点数保存，避免浮点误差。
- 首版不维护现金、银行卡或支付平台等账户余额，也不支持账户间转账。
- 首页名称为“记账”，英文为“Ledger”；页面显示今日摘要、快速记一笔和今日流水。
- 鼠标与键盘并重，支持 `Tab` 导航、`Return` 提交和 `⌘N` 新建账目。
- 设置可使用 macOS 标准快捷键 `⌘,` 打开，但侧边栏不显示快捷键提示。

### 3.2 分类

支出内置分类：

- 衣
- 食
- 住
- 行
- 娱乐
- 其他

收入内置分类：

- 工资
- 奖金
- 理财
- 退款
- 其他

分类规则：

- 用户手动选择分类。
- 未选择分类时，自动归入对应账目类型的“其他”。
- 用户可新增、重命名、排序和隐藏自定义分类。
- 自定义分类必须属于收入或支出其中一种类型。
- 内置分类随系统语言本地化；自定义名称属于用户内容，不自动翻译。
- “其他”不可隐藏或删除。
- 已被账目引用的自定义分类只能隐藏，历史账目继续保留引用。
- 自定义分类可选择 Lucide 图标和颜色。

### 3.3 日历

- 提供独立月历页面。
- 支持切换月份、选择日期和返回今天。
- 点击日期后调出当天的收入、支出与账目列表。
- 日期计算使用用户当前日历与时区，避免跨日和夏令时错误。

### 3.4 多选与合计

- 支持进入多选模式、逐条勾选、全选当天账目和取消选择。
- 只选择支出时显示支出总计；只选择收入时显示收入总计。
- 混合选择时同时显示收入、支出与净额。
- 批量删除必须确认，完成后提供撤销入口。

### 3.5 基础统计

- 显示本月收入、本月支出和本月结余。
- 显示分类占比。
- 显示简单的日或周趋势。
- 使用 Swift Charts 绘制图表。
- 统计只读取和聚合账目，不复制账目数据。

### 3.6 通用设置

“通用”设置包含：

- 默认账本币种；初始值为美元（USD）。
- 单个账本只使用一种币种，不进行汇率换算。
- 分类管理。
- 数据导入与导出。
- 备份与恢复。
- 软件更新：显示当前版本和“检查更新”按钮。
- 关于、版本、许可证和开源仓库链接。

### 3.7 外观设置

“外观”设置包含：

- 浅色、深色和跟随系统三种主题模式。
- 系统字体、编辑感衬线字体和圆角字体三种内置字体风格；全部使用系统字体能力，不捆绑第三方字体文件。
- 界面动效强度滑杆，范围为 0–100，默认 50。
- 当 macOS 开启“减少动态效果”时，系统设置优先于应用滑杆。
- 中文与英文切换。
- 切换语言后，应用名称、导航、设置、空状态、错误提示和内置分类整体切换。

### 3.8 AI 助手

AI 助手是独立一级页面，英文为“AI Assistant”，包含“AI 记账”和“账目分析”两种模式；“记账”页同时提供 AI 快捷入口。

AI 记账：

- 首版只提供文字输入，不申请麦克风权限。
- 用户仍可使用 macOS 系统听写在文本框中输入。
- 一次输入可包含一条或多条账目。
- AI 输出一组可编辑草稿，每张草稿包含金额、类型、分类、日期、时间和备注。
- 用户可修改或删除任一草稿，确认后才批量写入账本。
- 保存后的 AI 账目与手动账目没有权限或编辑能力差异。

账目分析：

- 用户可用自然语言询问完整账本，例如消费结构、时间趋势、分类变化或异常支出。
- 经用户授权后，分析包含全部账目与全部备注。
- 完整账本访问开关默认关闭。
- 首次开启时必须说明发送字段、远端处理、潜在费用和隐私影响。
- 只在用户主动发起分析时发送数据，不进行后台上传或后台分析。
- AI 分析为只读，不得修改、删除或新增现有账目。
- 当账本超出单次上下文限制时，按确定性批次处理全部记录，再生成最终综合分析。
- 每次批量分析记录源账目数、各批次账目数和总处理数；三者必须一致。

### 3.9 软件更新

- 更新入口位于“设置 → 通用 → 软件更新”。
- 使用 Sparkle 2 检查、验证、下载和安装发布版更新。
- 提供“检查更新”按钮和当前版本显示。
- 应用启动、退出和后台运行时均不自动检查，也不访问更新源。
- 只有用户点击“检查更新”后，应用才请求更新清单。
- 发现新版后展示版本号与发布说明，由用户确认后才下载和安装。
- 首版不启用自动下载或后台静默安装。
- 更新清单通过项目 GitHub Pages 托管，更新包链接指向 GitHub Releases 资产。
- 稳定版只接收稳定更新，不读取预发布版本或测试频道。
- 源码开发构建不执行自更新；更新功能只对签名发布构建启用。
- 更新检查不启用系统画像或遥测，仅请求 HTTPS 更新清单和用户确认后的更新包。

## 5. 核心用户流程

### 5.1 手动记账

1. 用户打开“记账”或按 `⌘N`。
2. 输入金额并选择支出或收入。
3. 手动选择分类；未选择时使用“其他”。
4. 可修改日期、时间和备注。
5. 保存后列表、日历和统计自动刷新。

### 5.2 AI 批量记账

1. 用户进入“AI 助手 → AI 记账”并输入自然语言。
2. 应用发送本次输入、当前日期、时区、语言、币种和可用分类。
3. 协议适配器将远端响应转换为统一草稿结构。
4. 本地校验金额、类型、日期和分类。
5. 用户逐条修改、删除或确认草稿。
6. 用户确认后通过账本仓库批量写入。

### 5.3 AI 完整账本分析

1. 用户进入“AI 助手 → 账目分析”并提出问题。
2. 应用检查完整账本访问授权；未授权时先解释并请求开启。
3. 应用读取全部账目，包括备注，并计算记录数量与分批方案。
4. 所有批次通过当前连接发送；任何批次失败时不伪造完整结果。
5. 应用核对处理记录数量后请求最终综合分析。
6. 界面展示分析答案、数据范围、处理记录数和所用连接。

### 5.4 日历回看

1. 用户进入“日历”。
2. 切换月份并选择日期。
3. 查看当天摘要和账目。
4. 打开任一账目进行编辑。

### 5.5 多选合计

1. 用户在流水列表进入多选模式。
2. 勾选账目或全选当天账目。
3. 底部选择栏实时显示收入、支出和净额。
4. 用户可取消选择或执行批量删除。

## 6. 视觉与交互设计

### 6.1 设计方向

产品采用一套组件、两套主题令牌：

- 浅色主题为“温暖编辑感”：纸张暖白、森林绿与陶土橙。
- 深色主题为“石墨工作室感”：石墨背景、苔藓绿与柔和荧光绿。
- 两种主题共享布局、字号、间距、图标和交互位置，切换主题不改变信息结构。

### 6.2 颜色令牌

浅色主题：

深色主题：

### 6.3 图标

- 所有功能图标统一使用 Lucide 开源矢量图标，保持相同线宽、圆角和视觉尺寸。
- 仓库中固定图标版本并保留 ISC 许可证声明。
- 不使用表情符号代替功能图标。
- 应用图标与项目封面为原创资产，遵循同一暖纸/石墨品牌语言。
- 设置入口使用明显的齿轮图标，但不在旁边显示快捷键提示。

### 6.4 动效

- 0：关闭非必要位移和弹性，只保留即时状态变化。
- 50：默认短时淡入、选择反馈和克制的弹性过渡。
- 100：完整的卡片插入、页面切换和图表过渡。
- 删除、保存和 AI 请求状态不依赖动画传递关键信息。

## 7. 数据模型

### 7.1 LedgerEntry

| 字段 | 类型 | 规则 |
|---|---|---|
| id | UUID | 主键 |
| kind | EntryKind | expense 或 income |
| amount | Decimal | 必须大于 0 |
| categoryID | UUID | 必须可解析，缺失时指向对应“其他” |
| note | String | 可为空 |
| occurredAt | Date | 用户可编辑 |
| createdAt | Date | 自动生成 |
| updatedAt | Date | 每次编辑更新 |

币种属于账本偏好，不逐条保存；首版不支持混合币种与汇率换算。

### 7.2 Category

| 字段 | 类型 | 规则 |
|---|---|---|
| id | UUID | 主键 |
| kind | EntryKind | 收入或支出 |
| systemKey | String? | 内置分类的稳定本地化键 |
| customName | String? | 自定义分类名称 |
| iconName | String | Lucide 图标键 |
| colorToken | String | 主题可适配颜色键 |
| sortOrder | Int | 用户排序 |
| isHidden | Bool | 隐藏后不出现在新账目选择器 |

### 7.3 AIConnection

非密钥配置可保存在本地偏好或 SwiftData：

| 字段 | 类型 | 规则 |
|---|---|---|
| id | UUID | 主键 |
| displayName | String | 用户自定义连接名 |
| protocolKind | AIProtocolKind | 四种受支持协议之一 |
| baseURL | URL | 用户填写并校验 HTTPS；本机地址可显式允许 HTTP |
| modelID | String | 用户填写，不内置厂家或模型列表 |
| isDefaultForEntry | Bool | AI 记账默认连接 |
| isDefaultForAnalysis | Bool | 账目分析默认连接 |
| keychainAccount | String | 指向钥匙串条目，不保存密钥正文 |

### 7.4 AIProtocolKind

首版支持：

- Chat Completions
- Responses API
- Messages API
- GenerateContent API

协议适配器将不同请求和响应统一为内部 `LedgerDraft` 与 `AnalysisResult`。

### 7.5 AppPreferences

使用 AppStorage 保存：

- 主题模式
- 字体风格
- 动效强度
- 应用语言
- 默认币种
- 完整账本访问授权
- 默认 AI 连接 ID

## 8. 技术架构

### 8.1 技术栈

- SwiftUI：原生 macOS 界面。
- SwiftData：本地账目与分类持久化。
- Swift Charts：基础统计图表。
- Observation：功能状态和业务规则。
- AppStorage：轻量偏好设置。
- Security/Keychain Services：API 密钥。
- URLSession：AI 协议网络请求。
- Sparkle 2：发布版更新检查、签名验证、下载与安装。
- XCTest 与 Swift Testing：单元和集成测试。

### 8.2 功能边界

- **LedgerFeature**：快速录入、流水、编辑、多选和撤销。
- **AIAssistantFeature**：AI 记账、完整账本分析、草稿确认。
- **CalendarFeature**：月份、日期和每日汇总。
- **InsightsFeature**：区间聚合和图表。
- **SettingsFeature**：通用、外观、AI 连接与授权、软件更新设置。
- **LedgerRepository**：SwiftData 的唯一账目与分类访问边界。
- **PreferencesStore**：主题、字体、语言、动效、币种和授权。
- **KeychainStore**：密钥读取、更新和删除。
- **ImportExportService**：CSV 导入导出与预览。
- **BackupService**：版本化 JSON 备份、校验、恢复和快照。
- **AIProtocolAdapter**：协议请求构建、响应解析和错误映射。
- **UpdateService**：封装 Sparkle 检查、状态、发布说明和用户触发操作。

界面不得直接操作 SwiftData；统计不得维护第二份账目；AI 不得直接写入数据库。

### 8.3 数据流

```text
SwiftUI 界面
  → 功能状态与业务校验
  → LedgerRepository
  → SwiftData 本地存储
  → 查询变化通知相关页面刷新
```

AI 连接数据流：

```text
用户主动请求
  → 授权与连接校验
  → KeychainStore 读取密钥
  → AIProtocolAdapter
  → URLSession 远端请求
  → 统一草稿或分析结果
  → 本地校验
  → 用户确认或只读展示
```

软件更新数据流：

```text
用户点击“检查更新”
  → UpdateService / Sparkle
  → GitHub Pages 上的签名 appcast.xml
  → 比较 CFBundleVersion
  → 展示 GitHub Releases 发布说明
  → 用户确认
  → 下载并验证签名更新包
  → 安装并重新启动应用
```

## 9. AI 协议与隐私设计

### 9.1 连接配置

- 用户可创建多个连接。
- 设置界面不提供厂家按钮或厂家列表。
- 每个连接只显示连接名称、协议、Base URL、API 密钥、模型 ID 和测试连接。
- AI 记账与账目分析可分别选择默认连接。
- 测试连接只发送最小测试内容，不发送账本。

### 9.2 结构化输出

AI 记账的统一草稿结构包含：

```json
{
  "entries": [
    {
      "kind": "expense",
      "amount": "18.00",
      "category": "食",
      "occurredAt": "2026-08-29T12:30:00+08:00",
      "note": "午饭",
      "needsReview": false
    }
  ]
}
```

- 金额以字符串传输并在本地转换为 Decimal。
- 缺失金额或日期歧义必须标记 `needsReview`。
- 未匹配分类时使用“其他”。
- 远端返回通过本地 schema 和业务校验后才能形成草稿。

### 9.3 完整账本分析

- 发送字段为日期、金额、收支类型、分类和完整备注。
- 不发送 API 密钥、应用偏好、备份文件、导出文件或与账本无关的本地数据。
- 大账本按稳定排序和固定大小分批；每条记录包含稳定 ID，避免重复或遗漏。
- 分批结果必须带已处理 ID 集合或计数，最终合并前核对覆盖率。
- 分析结果显示数据范围、总记录数、所用连接和是否分批。
- 应用不承诺远端服务不保留数据；首次授权明确要求用户阅读当前远端服务的隐私和费用政策。

### 9.4 密钥安全

- 密钥只保存于 macOS 钥匙串。
- 密钥输入框默认遮罩，不提供直接明文展示。
- 密钥不写入错误信息、分析日志、崩溃上下文、备份或导出。
- 设置提供“测试连接”“替换密钥”和“删除密钥”。

## 10. 导入、导出、备份与恢复

所有入口位于“设置 → 通用 → 数据”。

### 10.1 CSV

- 导出字段：发生时间、类型、金额、分类、备注、创建时间、修改时间。
- 导入支持中文和英文字段模板，并在写入前展示有效行、错误行和分类映射预览。
- 错误行不写入；用户可导出错误报告。
- 导入时不存在的分类可创建为自定义分类，或由用户映射到“其他”。

### 10.2 JSON 备份

- 使用带 schemaVersion 的版本化 JSON。
- 包含账目、分类和非敏感偏好。
- 不包含 API 密钥或 AI 远端响应。
- 恢复前验证格式、版本、数据关系和金额。
- 恢复前自动创建当前账本快照。

## 11. 错误处理

### 11.1 本地数据

- 金额为空、为零或格式错误时就地提示，不关闭录入区。
- SwiftData 写入失败时保留用户输入并提供重试。
- 删除使用确认与撤销。
- 导入失败不产生部分写入；批次作为事务提交。

### 11.2 AI

- 映射密钥无效、Base URL 错误、模型不存在、限流、余额不足、超时、服务故障和响应格式异常。
- 请求失败时保留原始输入和已有草稿。
- 格式异常可自动重试一次；仍失败则允许转为手动记账。
- 用户取消后停止后续批次，不保存未确认草稿。
- 完整账本任一批次失败时，结果标记为不完整且不生成伪装成完整的结论。
- AI 故障不得阻塞手动记账、日历、统计或数据管理。

### 11.3 软件更新

- 更新清单无法访问时，手动检查显示网络或源错误。
- 签名验证失败时拒绝安装并显示安全错误，不提供绕过按钮。
- 当前已经是最新版时给出明确反馈。
- 更新不兼容当前 macOS 版本时说明最低系统要求，不尝试安装。
- 下载取消或失败后保留当前应用版本，可由用户重新检查。

## 12. 测试策略

### 12.1 单元测试

- Decimal 金额精度。
- 收入、支出和混合多选净额。
- 默认“其他”分类。
- 自定义分类隐藏与历史引用。
- 日期边界、月份切换、时区和夏令时。
- 统计聚合与空数据。
- 四种协议到统一草稿/分析结果的转换。
- AI 分批覆盖率和无重复校验。
- 语言、主题、字体和动效偏好。

### 12.2 集成测试

- SwiftData 仓库增删改查。
- CSV 导入预览、错误行和导出往返。
- JSON 备份、快照和恢复往返。
- Keychain 保存、读取、替换和删除。
- API 密钥不进入任何序列化产物。
- 每种协议使用本地模拟服务器覆盖成功、鉴权失败、限流、超时和畸形响应。
- Sparkle 更新清单解析、版本比较、无新版、网络失败、签名失败和不兼容系统版本。

### 12.3 UI 与可访问性测试

- 一级导航和三个设置分栏。
- 快速新增、编辑、多选和撤销。
- AI 多草稿确认。
- 完整账本访问授权。
- 软件更新当前版本和手动检查按钮；验证启动及后台运行不会产生更新请求。
- 中英文完整切换。
- 浅色、深色和跟随系统。
- 键盘导航与 VoiceOver 标签。
- 小窗口、空状态和大量账目状态。

### 12.4 CI 原则

- 默认 GitHub Actions 不调用真实 AI 服务。
- 真实协议冒烟测试由维护者手动触发并自行注入临时密钥。
- CI 日志必须对敏感字段进行脱敏。
- 发布工作流必须使用旧版与新版签名构建执行一次端到端更新验收。

## 13. 开源与发布

- 仓库使用 MIT 许可证。
- README 提供中英文产品介绍、截图、构建步骤、隐私说明和 AI 连接说明。
- 提供 `CONTRIBUTING.md`、行为准则、问题模板和安全报告方式。
- 仓库不包含密钥、个人账本、真实备份或 AI 请求样本。
- 首版以源码构建和 GitHub Releases 为发布渠道。
- 若配置 Apple 开发者签名与公证凭据，则发布签名、公证后的安装包；未配置时不得声称安装包已经公证。
- 发布标签触发工作流生成 GitHub Release、签名更新包、发布说明和 Sparkle `appcast.xml`。
- `appcast.xml` 发布到仓库的 GitHub Pages；其中下载地址指向对应 GitHub Release 资产。
- 更新包使用 Sparkle EdDSA 签名；公钥随应用发布，私钥仅保存在发布环境的钥匙串或 GitHub Actions Secrets，不进入仓库。
- 自动检查、自动下载和自动安装全部关闭；只有用户点击按钮后才访问更新源。
- 正式版本遵循语义化版本号。

## 14. v1 非目标

- iPhone、iPad、Windows 或网页版本。
- 预算、账单提醒、同比环比、资产或投资管理。
- 票据 OCR。
- 应用内麦克风按钮和连续语音对话。
- 后台自动上传或后台 AI 分析。
- AI 自动修改、删除或覆盖已有账目。
- 混合币种和汇率换算。
- 厂家或模型推荐列表。
- 自动或后台检查、下载、安装软件更新。
